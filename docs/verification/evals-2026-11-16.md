# Plugin evals — 2026-11-16

`claude plugin eval` on Claude Code 2.1.311, against the v1.8.0 release
candidate. Every case is read-only (Read, Glob, Grep, Skill) and runs once, so
this is a smoke signal, not a distribution. LLM graders vote three times.

Reproduce from the repository root:

```bash
claude plugin eval . --runs 3                               # with/without plugin
claude plugin eval . --model haiku --ablation none --runs 3 # one model, plugin only
```

## With and without the plugin (harness default model)

| Case | With plugin | Without plugin |
|---|---|---|
| review-pasted-diff | 1.0 | 0.5 |
| consult-architecture-proposal | 1.0 | 0.0 |
| refactor-plan | 1.0 | 0.0 |

The first run scored the plugin arm the same as the baseline. Every command
named only the symlink path, so a plugin-loaded session could not find the
workflows. v1.8.0 adds the `${CLAUDE_PLUGIN_ROOT}` path first, and the
packaging check now requires it. The table above is the run after that fix.

## Smaller models (plugin only)

| Case | Haiku | Sonnet |
|---|---|---|
| review-pasted-diff | 1.0 | 0.5 |
| consult-architecture-proposal | 1.0 | 1.0 |
| refactor-plan | 0.0 | 1.0 |

`refactor-plan` first failed on both models because the sandbox had no code and
both asked for it, as the workflow says. The case now states that the code is
unavailable; Sonnet then passed. Haiku still fails: it treated the command's
activation-probe preamble as an unrelated instruction and skipped the workflow
files. This is a known limitation on Haiku.

## Limits

- One run per case; scores can move between runs.
- The harness default model is not recorded in the eval output.
- Graders are LLM judges (Haiku by default, Sonnet for the re-runs above). A
  failing vote was read against the response before it was recorded here.
- Codex CLI and Cursor Agent were not exercised by these evals.
